# 团队成员名单

本文档汇总当前项目中的 Cursor subagent 团队成员，供主 agent 在拆分任务、分配工作、轻量严格模式执行和结果审核时参考。

成员文件位于 `.cursor/agents/`，调用时使用对应的 `/agent-name`。

## 相关规则

- 完整协作制度见 `Docs/team-collaboration-rules.md`。
- 项目级 Cursor 规则位于 `.cursor/rules/`，默认始终生效。
- 团队默认由主 agent 分配给合适 subagent 执行，主 agent 负责分发、范围控制、审核汇总和最终回复。
- 本项目由 agent 自主驱动持续开发；除非用户主动终止，否则完成一个任务或版本后，制作人应继续决定下一阶段方向。
- 用户主要通过根目录 `42.md` 同步体验和想法，制作人必须持续参考。
- 每个成员允许使用 `Workspaces/<agent-name>/` 作为个人工作空间；有意义的草稿、报告和任务记录应提交进 Git，临时缓存不提交。
- 每个成员完成自己的任务后，应自检并说明修改范围、验证方式和残留风险，再按 Git 规则提交并推送。

## 分配原则

- 制作方向、玩法愿景、玩家体验判断：优先交给 `/space-game-producer`。
- 进度、排期、任务拆分、跨职能统筹：优先交给 `/game-project-manager`。
- 系统、数值、玩法规则等设计问题：先交给对应策划类成员。
- 代码实现、工具、原型、修复和打磨：交给开发类成员。
- UI、资产、整体风格和图片生成：交给美术类成员。
- 软件安装、环境配置、系统维护：交给 `/it-engineer`。
- 审核任务应优先选择更资深、职责更匹配的成员，避免让执行者自审。
- 版本规划、多步骤任务、跨职能任务和发布任务必须让 `/game-project-manager` 介入。
- 涉及可玩内容时，任务拆分和审核必须关注验证计划、浏览器运行反馈、日志、自动化测试和残留风险。
- 除涉及本机环境的危险操作外，其余项目事项默认由 `/space-game-producer` 拥有决定权。
- 核心玩法、系统规则、数值框架和存档数据属于项目高风险任务，应走专项审核、PM 汇总审核和制作人最终决定。
- 环境配置、权限提升、删除覆盖类操作属于本机环境危险操作，必须先获得用户确认。

## 常见分工示例

- 继续推进项目或完成阶段后没有新指令：`/space-game-producer` 先检查 `42.md` 并决定下一阶段方向，`/game-project-manager` 再拆分任务。
- 评估“太空探索核心循环是否好玩”：`/space-game-producer` 主评，必要时 `/game-system-designer` 补系统方案。
- 拆分一个版本计划：`/game-project-manager` 主拆，必要时让各职能成员补充工作量和风险。
- 设计舰船升级和战斗公式：`/game-numerical-designer` 主导，`/game-system-designer` 复核系统闭环。
- 快速验证新玩法：`/game-prototype-developer` 执行，`/space-game-producer` 或 `/game-system-designer` 审核体验。
- 实现正式玩法功能：`/game-client-developer` 执行，复杂技术由 `/game-code-god` 评审或攻关。
- 打磨已有操控手感：`/game-polish-developer` 执行，制作人或系统策划确认体验目标。
- 建立浏览器冒烟、Playwright 回归、日志采集或发布验证脚本：`/game-tools-developer` 执行，PM 审核验证闭环。
- 判断是否引入 Phaser、PixiJS、Unity WebGL、Vite、ESLint 等工具链：制作人提出体验与效率问题，PM 统筹成本风险，`/game-tools-developer` 或 `/it-engineer` 做技术评估。
- 制作 UI mockup 或图标：`/game-ui-artist` 执行，`/game-art-director` 审核风格一致性。
- 生成舰船、道具或场景资产方案：`/game-asset-artist` 执行，`/game-art-director` 审核整体风格。
- 安装 Unity、Blender、SDK 或外部工具：`/it-engineer` 先检查环境和风险，再执行安装配置。
